# Tree page contract inventory

This page maps the public Tree contract in [Tree docs](../../../../../../../../../docs/tree.md), [Tree API](../../../../../../../../../projects/ui/src/lib/components/tree/kui-tree.component.ts), [node type](../../../../../../../../../projects/ui/src/lib/components/tree/kui-tree-node.interface.ts), [styles](../../../../../../../../../projects/ui/src/lib/components/tree/kui-tree.css), [theme tokens](../../../../../../../../../projects/ui/src/lib/theme/create-kui-theme.ts), and [unit tests](../../../../../../../../../projects/ui/src/lib/components/tree/kui-tree.component.spec.ts) to the live examples in this page. The page imports Tree only from `@kikita-labs/ui`; the app shell owns theme and language.

## Public inputs and models

| API                                 | Type, default, and observed contract                                                                                                                                                                                        | Page example or omission                                                                                                                                                                                                                         |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `mode`                              | `'display' \| 'checkable'`, default `display`. Display selects one row; checkable renders checkboxes and cascades changes through descendants.                                                                              | The minimal display example omits `mode`; the checkable example uses explicit checkable mode and starts with one of two child leaves checked to show a mixed parent.                                                                             |
| `size`                              | `KuiSize \| undefined`; local value, then root size default, then `md`. `sm`, `md`, and `lg` have Tree-specific styles. `xs` is accepted by the type but has no dedicated Tree styling and renders like the base/`md` size. | The minimal example omits `size` and E2E asserts its current effective `md` value. The size card shows `sm`, `md`, and `lg`; `xs` is omitted because it has no distinct Tree rendering.                                                          |
| `data`                              | `readonly KuiTreeNode[]`, default `[]`. An empty array renders no rows and there is no component empty-state treatment.                                                                                                     | Every visible example provides a small translated deterministic tree. Empty data is omitted because it would be blank rather than a useful visual state.                                                                                         |
| `ariaLabel`                         | `string`, default `Tree`; names the tree container.                                                                                                                                                                         | Each instance provides a translated accessible name so the same page remains correctly named after the runtime language switch.                                                                                                                  |
| `mobile`                            | `boolean`, default `false`; documented to enlarge toggle targets to 44px.                                                                                                                                                   | The mobile card enables it at `md`, the size where the target currently measures 44px. The documented `sm` and `lg` mobile combinations are omitted because their source CSS overrides the target size.                                          |
| `value` / `valueChange`             | `string \| null`, default `null`; two-way single selection in display mode.                                                                                                                                                 | The default example binds `[(value)]`; real keyboard selection updates the visible status and selected treeitem. The deprecated `selected` alias is not used.                                                                                    |
| `selected` / `selectedChange`       | Deprecated compatibility model synchronized with `value`; planned removal in the next major version.                                                                                                                        | Intentionally omitted; new consumer code should use `value`.                                                                                                                                                                                     |
| `checkedIds` / `checkedIdsChange`   | `string[]`, default `[]`; two-way checked-id collection in checkable mode. A parent may report `true`, `false`, or `mixed` based on descendant states.                                                                      | The checkable example starts with one child checked, uses Space to check the other, and includes a disabled sibling whose native checkbox remains disabled and unchecked.                                                                        |
| `expandedIds` / `expandedIdsChange` | `string[]`, default `[]`; two-way expanded-node collection.                                                                                                                                                                 | The checkable sample initializes its branch expanded to make the mixed state visible, then its localized live status reflects the bound collection as keyboard input collapses and expands that branch.                                          |
| `loadChildren`                      | Optional `(node) => Promise<readonly KuiTreeNode[]>`; absent by default. A successful lazy result is cached for the tree instance, then the node expands.                                                                   | The lazy example returns fixed children after a fixed short delay. E2E checks loading, loaded labels, and expansion. Missing callback and rejected promises are omitted because the former has no visible result and the latter has no error UI. |

`KuiTreeNode` requires a stable `id` and visible `label`; `icon` supports `folder` and `file`; optional `children`, `disabled`, `lazy`, and consumer `data` remain available. Folder/file icons appear in display fixtures, `children` appear in display and checkable fixtures, `disabled` appears on a leaf, and `lazy` is exercised by the successful loader. Consumer `data` is not rendered by Tree and is omitted. There is no documented custom icon template, virtualization, appearance, shape, density, validation, or empty-state API, so the page invents none. The checkable treeitem's accessible name includes both its row label and the checkbox's identical `aria-label`; its parent is therefore exposed as `Project files Project files`, which the E2E locates by its actual name.

## Visual catalogue and behavior

- **Default and keyboard:** the default `display`/effective-`md`/non-mobile instance has localized data and name, a null initial value, and a live selected summary. Page-owned node labels refresh after both the active-language event and Transloco's `translationLoadSuccess`, so lazy scope data is translated before Tree computes its accessible item names. E2E captures a pointer-hovered row (see discrepancy 7), tabs to the first treeitem, uses Right/Down/Left/End/Home and letter type-ahead, selects with Enter, and expands/collapses with Space. It captures the real keyboard-selected `:focus-visible` row and updated summary; no pseudo-state is simulated with page CSS.
- **Sizes:** `sm`, `md`, and `lg` use the same short tree so typography, row density, and icons can be compared without changing content. Only one component input changes within each example.
- **Checkable:** the visible `check-group` starts mixed (`checked-leaf` checked, `open-leaf` unchecked). Its localized live status reflects the consumer-bound `expandedIds` model; Left/Right collapse and expand the parent and update the status. Space on the unchecked leaf makes the parent checked. The disabled leaf is an independent sibling, so it does not confound the parent state; its treeitem is disabled and its native checkbox cannot be toggled.
- **Lazy loading:** the display-mode lazy folder starts collapsed and loads two fixed children after a fixed 120ms delay. E2E installs the browser clock after the page is ready, captures the idle state, expands it with ArrowRight, waits for the spinner status to render, pauses time, and captures that pending state before running the clock for 120ms. It then verifies the localized child labels and page-owned localized completion status before capturing the resolved state, resumes the clock, collapses the folder, and reopens it to verify cached children do not trigger another loader. It does not seed a checked parent or represent loader failure.
- **Mobile:** the real `mobile` input is enabled for the `md` tree. E2E asserts the 44px row and toggle dimensions. The page makes no claim about defective `sm`/`lg` mobile combinations and does not enlarge them with page CSS.
- **Responsive and SSR evidence:** the visual spec requests named section screenshots at desktop and tablet/320px widths, checks page overflow, and requests the route over HTTP before browser rendering. The 320px capture uses a 1024px viewport height so the size catalogue fits inside the app shell's scrollable workspace; the page itself remains vertically scrollable at shorter heights. The page uses no browser globals; lazy loading starts only after user interaction.
- **Translation:** page-owned labels, tree labels, summaries, and group names use the `tree` EN/RU scope. The page tracks both language changes and successful translation-load events so node data recomputes when the lazy scope arrives; the spec switches language at runtime and checks that the default tree and lazy children update. The recursive node template's spinner accessible name remains hardcoded as English `Loading`; the Russian interaction test records that library-source gap.

The effective size can inherit a root size provider when local `size` is omitted; E2E asserts the Playground's current `md` result rather than claiming that `md` overrides a provider. The minimal default example uses only the data tree, a localized accessible name, and `value` for its interactive selection result. No independent output event exists beyond model change outputs listed above.

## Source discrepancies and intentional omissions

1. **Mobile target collision:** `docs/tree.md` promises a 44px mobile toggle target, and the base mobile rules set 44px, but later size rules in `tree.css` override toggle dimensions for `sm` and `lg`. The CSS resolves toggle dimensions to `sm` 16px, `md` 44px, and `lg` 24px. Only the passing `md` combination appears in the catalogue; E2E does not assert the defective combinations.
2. **Disabled expandable parents:** docs say disabled nodes cannot be expanded, but pointer toggle and ArrowRight/ArrowLeft handling do not guard `node.disabled`. This defect is intentionally omitted from the normal catalogue and E2E; only a disabled leaf is shown.
3. **Checked lazy parents:** `checkedState` changes from the lazy node's own id to its descendants after loading and does not cascade an existing parent check to new children. This state transition is intentionally omitted; the lazy example is display mode and has no checked model.
4. **Loader rejection:** `loadNode` has a `finally` block but no rejection handler or error UI, so a rejected callback leaves the tree without a recoverable error state. Failed loading is intentionally omitted.
5. **Spinner localization:** the recursive node template labels its loading status with hardcoded English `Loading`. The Russian E2E interaction asserts this observed string as an unresolved library-source discrepancy.
6. **Enter on lazy nodes:** `docs/tree.md` lists Enter among the keys that trigger the first lazy load, but `onKeydown` handles Enter only as display-mode selection; Space, ArrowRight, and toggle click load children. The page exercises ArrowRight only.
7. **Hover contrast inside cards:** `--kui-tree-row-bg-hover` resolves to `--kui-color-surface`, the same token `kuiCard` uses for its default background, so a hovered row inside the example card is visually indistinguishable from an idle row in both themes. The hover E2E proves the real `:hover` match and a computed background change from the idle transparent row; `tree-hover-desktop.png` therefore looks identical to the default capture and is kept as evidence of this library-token gap, not as proof of a visible hover treatment.

## E2E scope

`e2e/tree-playground.visual.spec.ts` scopes Tree hosts and rows with accessible role/name locators, using the actual checkable item name that combines row text with the checkbox's `aria-label`. It asserts visible localized row labels and ARIA states, and covers the default `value` binding and keyboard paths, real pointer-hover and keyboard-selected `:focus-visible` captures, consumer `expandedIds` updates through the localized status, initial mixed and disabled-leaf states, successful lazy loading with time paused only after the spinner is observed and `runFor(120)` to render the resolved state, then resumed time for the collapse/reopen cached-loader assertion, the passing `md` mobile target, EN/RU translation including the spinner localization discrepancy, HTTP/SSR markup, responsive overflow, and named catalogue screenshots. Requested screenshot names are `tree-default-desktop.png`, `tree-hover-desktop.png`, `tree-selected-focus-visible-desktop.png`, `tree-sizes-desktop.png`, `tree-checkable-desktop.png`, `tree-lazy-idle-desktop.png`, `tree-lazy-loading-desktop.png`, `tree-lazy-loaded-desktop.png`, and `tree-mobile-md-desktop.png`; tablet and mobile screenshots are `tree-sizes-{tablet-768,mobile-320}.png`, `tree-checkable-{tablet-768,mobile-320}.png`, and `tree-mobile-md-{tablet-768,mobile-320}.png`.
