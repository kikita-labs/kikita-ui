# Avatar page contract inventory

This inventory maps the implemented Avatar Playground page to the source contract. It was cross-checked against `docs/avatar.md`, the public barrels, the implementation and templates, the colocated unit tests, `avatar.css`, theme generation, the shared Skeleton primitive, root size-default rules, and the existing Avatar consumer in `projects/playground`.

## Public surface

The public import path is `@kikita-labs/ui`. `projects/ui/src/public-api.ts` re-exports the component barrel; `projects/ui/src/lib/components/index.ts` re-exports the Avatar barrel; and `projects/ui/src/lib/components/avatar/index.ts` exports:

- `KuiAvatarComponent` (`kui-avatar`)
- `KuiAvatarGroupComponent` (`kui-avatar-group`)
- `KuiAvatarItem`
- `KuiAvatarShape`: `'circle' | 'square'`
- `KuiAvatarSize`: `'xs' | 'sm' | 'md' | 'lg' | 'xl' | '2xl'`
- `KuiAvatarStatus`: `'online' | 'away' | 'busy' | 'offline'`

Neither component declares an output, model, or consumer-facing method. `onImageError()` is a template handler, not a public API. Avatar interaction belongs to a native consumer-owned button wrapper as shown by `docs/avatar.md`.

## Style and token audit

The runtime source is `projects/ui/src/styles/avatar.css`, inside `@layer kui.components`, imported by the public `projects/ui/src/styles/kikita-ui.css` entry point. The page must consume those styles and only add layout rules. The style uses these Avatar token families:

- Dimensions: `--kui-avatar-size-xs`, `-sm`, `-md`, `-lg`, `-xl`, `-2xl` resolve to 20, 24, 32, 40, 48, and 64 CSS pixels. Font-size tokens follow the matching text scale.
- Shape: `--kui-avatar-radius-circle`, `--kui-avatar-radius-square`, and square size overrides.
- Fallback: `--kui-avatar-bg-fallback`, `--kui-avatar-icon-color`, palette `p1`–`p7` bg/fg pairs, `--kui-avatar-font-weight`, and `--kui-avatar-border`.
- Status: `--kui-avatar-status-size-*`, `--kui-avatar-status-border-width-*`, and `--kui-avatar-status-border`; fill colors come from `--kui-color-success-fill`, `--kui-color-warning-fill`, `--kui-color-danger-fill`, and `--kui-color-text-disabled`.
- Group: `--kui-avatar-group-overlap-*`; overflow uses `--kui-avatar-overflow-bg`, `--kui-avatar-overflow-text`, and `--kui-avatar-overflow-font-size`.
- Consumer action: `--kui-avatar-overlay-hover`, `--kui-avatar-overlay-active`, `--kui-avatar-action-radius`, `--kui-avatar-focus-ring-w`, `--kui-avatar-focus-ring-off`, and `--kui-avatar-focus-ring-color`.
- Loading: the shared `--kui-skeleton-*` tokens and global skeleton background/highlight tokens.

Avatar color palettes are explicitly defined in both light and dark theme maps in `projects/ui/src/lib/theme/create-kui-theme.ts`. The theme test checks the Avatar size and palette seed values. Avatar's square sizes, statuses, group overlap, overflow treatment, and action focus styles are source styles, not page-authored variants.

## Accessibility, lifecycle, and SSR evidence

- With image content, the component exposes a native `<img>` with resolved `alt`; the custom host has no duplicate image role/name. With initials or icon content, the host has `role="img"` and `aria-label`, while the visible initials/icon are hidden from the accessibility tree.
- Status dots are `aria-hidden`; the English status suffix is added to the image/fallback name.
- Loading removes the Avatar host role/name and the child Skeleton is `aria-hidden`.
- The group is a named `role="group"`; overflow is an individual named image.
- Interactive use follows the documented native `button.kui-avatar-action` wrapper with its own accessible name and a page-owned 44×44 minimum touch target. The component itself is not focusable or clickable.
- The implementation uses Angular inputs/computed/signals, has no generated ids or module-level browser globals, and makes no manual DOM mutations. A provided image is serialized as ordinary `<img>` markup; an error changes to fallback content only after the browser emits its image event.
- `avatar.css` does not set dark/light values directly; its palette and semantic colors resolve from the theme tokens. No Avatar-specific forced-colors override or screen-reader review is recorded by the source.

## Discrepancies, test coverage, and existing consumers

`docs/avatar.md` documents all individual and group input names, types, ordinary defaults, image fallback, status labeling, and group overflow. Cross-checking the source and global default rules found two documentation limitations for parent review:

1. The Avatar API table describes `size` as defaulting to `md` but does not say that an omitted local input inherits `KikitaUiDefaults.size` before reaching `md`. The current Playground root config does not set that option, so this page visibly resolves to `md`.
2. Source status suffixes (`online`, `away`, `busy`, `offline`) and group overflow labels (`N more`) are hard-coded English. The source doc notes the status suffix but does not identify that it is not localized. Avatar and Group have no locale input or injected translator.

`docs/avatar.md` names an external Claude Avatar spec but does not include an accessible tracked approval record. This page follows the agreed component-page catalogue contract and reproduces existing Avatar source values/styles only; it does not change library Avatar visuals or styles. The existing consumer in `projects/playground/src/app/pages/avatar/` covers basic content, the six sizes, both shapes, all statuses, all seven palette slots, loading, failed image fallback, group cases, and button composition; it uses a remote `pravatar.cc` image URL and is not the deterministic reference implementation. The routed Playground page is implemented under `src/app/features/playground/pages/data-identity/avatar/`.

The colocated Avatar unit suite currently verifies initials/name/status semantics, failed-image fallback to initials, loading content suppression and circle Skeleton shape, group `max` overflow and group label/size/shape attributes, palette numeric coercion/clamping, and valid static `max` coercion. It does not directly test all six sizes, both shapes, the icon fallback, explicit initials normalization, `alt`, every status, loading-square/status combination, group defaults/no-overflow, invalid/fractional `max`, root-size inheritance, or button-wrapper focus styles. Theme unit coverage checks an Avatar size token and light/dark palette values. The page/E2E coverage below is intended to expose the full visible catalogue; it does not replace those source test gaps.
