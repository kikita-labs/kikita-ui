# Chart page contract inventory

This page maps the public Chart contract to the live examples on `/components/chart`. It is the durable record of the accepted contract-to-example mapping; API reference stays in the docs app. Sources audited on 2026-09-29 against branch `release/2.x`:

- [Chart docs](../../../../../../../../../docs/chart.md) and [design provenance](../../../../../../../../../docs/design-provenance.md) (loading/marker/center-content design gaps).
- [Public types](../../../../../../../../../projects/ui/src/lib/components/chart/chart.types.ts) and the four components: [line](../../../../../../../../../projects/ui/src/lib/components/chart/kui-line-chart.component.ts), [bar](../../../../../../../../../projects/ui/src/lib/components/chart/kui-bar-chart.component.ts), [scatter](../../../../../../../../../projects/ui/src/lib/components/chart/kui-scatter-chart.component.ts), [donut](../../../../../../../../../projects/ui/src/lib/components/chart/kui-donut-chart.component.ts), plus their templates, the [standalone legend](../../../../../../../../../projects/ui/src/lib/components/chart/kui-chart-legend.component.ts) and its [item directive](../../../../../../../../../projects/ui/src/lib/components/chart/kui-chart-legend-item.directive.ts).
- Helpers: [keyboard navigation](../../../../../../../../../projects/ui/src/lib/components/chart/chart-keyboard-nav.util.ts), [tooltip controller](../../../../../../../../../projects/ui/src/lib/components/chart/chart-tooltip.util.ts), [color resolution](../../../../../../../../../projects/ui/src/lib/components/chart/chart-color.util.ts), [styles](../../../../../../../../../projects/ui/src/styles/chart.css), and the theme tokens in `create-kui-theme.ts`.
- Component unit specs next to each component.

The page imports Chart only from `@kikita-labs/ui`; the shell owns theme and language. All data is fixed in `constants/chart-values.const.ts`; labels, series names, categories, slice names, and tooltip text come from the `chart` EN/RU scope. Nothing uses network, randomness, or dates. Chart component styles are not overridden.

## Visual catalogue and behavior

Each group below is a `role="group"` named after its visible heading, and each chart is a `graphics-document` with a unique translated name.

- **Minimal chart:** one single-series line chart with `series`, `categories`, and a name only. E2E asserts default `md` viewBox, no legend, seven marks, and the default label `Sessions · Mon: 120`.
- **Line and area:** three-series line, two-series area, line with gaps, area with gaps, explicit colors. E2E hides and restores a series through the legend, checks area paths and mark counts, and checks that legend hover dims other lines and mark hover activates its legend entry.
- **Bar orientation and stacking:** single, vertical/horizontal grouped, vertical/horizontal stacked, diverging, and gaps. E2E checks bar counts, keeps the grouped axis stable and recomputes the stacked axis on legend hide.
- **Scatter and bubble:** two-series scatter, single-series scatter, and bubble. E2E checks mark counts, that each point has an aria-hidden visual dot, and that bubble radii vary.
- **Donut and slices:** default labels include the share (`Free: 40 (40%)`); hiding a slice re-partitions to `62%` and restoring returns to `40%`.
- **Axes, sizes, loading/empty, formatting, legend:** as in the input table.
- **Alternative table:** each type toggles to its table and back. Line shows exact values (`1234`, not `1.2K`) with `Category` plus series columns; scatter shows `Series`/`X`/`Y`, bubble adds `R`; donut shows `Label`/`Value`.
- **Interactions:** hover shows one shared tooltip (`role="tooltip"`) that retargets between marks and disappears when the pointer leaves; focus shows the same tooltip; Tab enters at the roving tab stop and leaves to the Table button; arrow keys, Home, and End move the roving tab stop (see discrepancy 3 for focus).

Omitted on purpose (unsupported or not a Chart feature): zoom/pan, donut center text or sum, marker shapes or patterns, configurable inner radius, log or clamped value axes, custom empty or loading content. None is invented on the page.

## Source discrepancies and known gaps

Recorded, not fixed here. Library work belongs to Plan 24; docs, changelog, and roadmap are intentionally untouched.

1. **Axis titles are not rendered.** `axes.xTitle`/`yTitle` are typed and documented as "rendered outside the SVG", but no chart template reads them. The page does not show them.
2. **Scatter tooltip point is wrong for `x`.** The formatter receives the SVG pixel coordinate as `KuiChartPoint.x` (a custom formatter printed `age 57.14285714285714` for a point at age 22) and `r` is not passed for bubbles. The default scatter text also omits `x`. The page's scatter tooltip therefore uses only the series name and `y`.
3. **Arrow keys do not move DOM focus.** Arrow keys, Home, and End update the roving `tabindex` but never focus the adjacent mark in the browser, for all four chart types: the handlers call `.focus?.()` on the `ElementRef` returned by `viewChildren`. Unit tests hide this because of a jsdom guard. E2E asserts the supported tab-stop behavior and carries a `test.fixme` for focus following the arrow.
4. **Event replay error.** Pressing an arrow key before hydration finishes logs `preventDefault called during event replay` from the chart keydown handler. E2E waits for hydration (mark ids switch to the client counter) before keyboard steps.
5. **Unstable SSR ids.** Chart ids come from a module-level counter, so server-rendered ids keep growing across requests (`kui-line-chart-97-mark-0`) while the client restarts at 1 (`kui-line-chart-1-mark-0`); ids are rewritten on hydration.
6. **Built-in English strings.** `No data`, `Loading chart`, the `Table`/`Chart` toggle, table headers (`Category`, `Series`, `X`, `Y`, `R`, `Label`, `Value`), and `aria-roledescription` values are hardcoded English. The RU E2E asserts this observed state.
7. **Bar loading overflow.** The bar skeleton (`8` bars at `10%` plus fixed gaps and padding) overflows containers narrower than about 452px (estimated from the CSS, observed in a 262px cell and at a 320px viewport). The page gives the desktop bar skeleton a full-width row, and narrow captures use the other three skeletons.
8. **Fixed axis padding and nominal-size density.** Long tick labels or narrow containers clip or crowd labels (`Business Enterprise` touch at `sm` and in narrow cells; a `4200%` format clipped its value axis, so the page uses a short `4.2k` format). This is the documented Known gap.
9. **Stale JSDoc.** `chart.types.ts` says series colors default to five `--kui-chart-series-*` tokens; the implementation and theme define eight. The line `tooltip` JSDoc omits the category part of the default text.
10. **Loading and marker designs** have no approved source (docs/design-provenance.md), so skeleton shapes are shown as they are and are not review-approved visuals.

## E2E scope

`e2e/chart-playground.visual.spec.ts` uses `getByRole` for groups, buttons, tables, status, columns, and tooltips; charts and marks are located by their ARIA roles and attribute values because Playwright does not model `graphics-document` or `graphics-symbol`. It covers server HTML and hydration without console errors, the minimal example, every input above, legend, table, tooltip, and roving-tab-stop keyboard behavior, EN/RU with a runtime switch (Russian text is read from `ru.json`, never hardcoded), page-level overflow at 768px and 320px, and named screenshots:

- Desktop: `chart-minimal`, `chart-minimal-focus-visible`, `chart-line-area`, `chart-bars`, `chart-bars-stacked-hidden`, `chart-scatter-bubble`, `chart-donut`, `chart-axes`, `chart-sizes`, `chart-states`, `chart-formatting`, `chart-legend`, `chart-legend-custom-hidden`, `chart-tables`.
- Tablet 768px and mobile 320px: `chart-minimal`, `chart-line-three`, `chart-donut` (three slices), `chart-scatter-loading`, `chart-line-empty`.

The viewport is 2400px tall so every named group sits inside the shell's scrolling workspace when captured. The shared route spec (`component-pages.spec.ts`) includes `/components/chart` in its SSR, hydration, selected-navigation, and 320/768/1440 overflow checks.
