# Chart page contract inventory

This page maps the public Chart contract to the live examples on `/components/chart`. It is the durable record of the accepted contract-to-example mapping; API reference stays in the docs app. Sources audited on 2026-09-29 against branch `release/2.x`:

- [Chart docs](../../../../../../../../../docs/chart.md) and [design provenance](../../../../../../../../../docs/design-provenance.md) (loading/marker/center-content design gaps).
- [Public types](../../../../../../../../../projects/ui/src/lib/components/chart/chart.types.ts) and the four components: [line](../../../../../../../../../projects/ui/src/lib/components/chart/line/kui-line-chart.ts), [bar](../../../../../../../../../projects/ui/src/lib/components/chart/bar/kui-bar-chart.ts), [scatter](../../../../../../../../../projects/ui/src/lib/components/chart/scatter/kui-scatter-chart.ts), [donut](../../../../../../../../../projects/ui/src/lib/components/chart/donut/kui-donut-chart.ts), plus their templates, the [standalone legend](../../../../../../../../../projects/ui/src/lib/components/chart/legend/kui-chart-legend.ts) and its [item directive](../../../../../../../../../projects/ui/src/lib/components/chart/legend/kui-chart-legend-item.ts).
- Helpers: [keyboard navigation](../../../../../../../../../projects/ui/src/lib/components/chart/core/chart-keyboard-nav.util.ts), [tooltip controller](../../../../../../../../../projects/ui/src/lib/components/chart/core/chart-tooltip.util.ts), [color resolution](../../../../../../../../../projects/ui/src/lib/components/chart/core/chart-color.util.ts), [styles](../../../../../../../../../projects/ui/src/lib/components/chart/kui-chart.css), and the theme tokens in `create-kui-theme.ts`.
- Component unit specs next to each component.

The page imports Chart only from `@kikita-labs/ui`; the shell owns theme and language. All data is fixed in `constants/chart-values.const.ts`; labels, series names, categories, slice names, and tooltip text come from the `chart` EN/RU scope. Nothing uses network, randomness, or dates. Chart component styles are not overridden.

## Visual catalogue and behavior

Each group below is a `role="group"` named after its visible heading, and each chart is a `graphics-document` with a unique translated name.

- **Minimal chart:** one single-series line chart with `series`, `categories`, and a name only. E2E asserts the chart name, no legend, seven marks, and the default label `Sessions · Mon: 120`.
- **Line and area:** three-series line, two-series area, line with gaps, area with gaps, explicit colors. E2E hides and restores a series through the legend, checks area paths and mark counts, and checks that legend hover dims other lines and mark hover activates its legend entry.
- **Bar orientation and stacking:** single, vertical/horizontal grouped, vertical/horizontal stacked, diverging, and gaps. E2E checks bar counts, keeps the grouped axis stable and recomputes the stacked axis on legend hide.
- **Scatter and bubble:** two-series scatter, single-series scatter, and bubble. E2E checks mark counts, that each point has an aria-hidden visual dot, and that bubble radii vary.
- **Donut and slices:** default labels include the share (`Free: 40 (40%)`); hiding a slice re-partitions to `62%` and restoring returns to `40%`.
- **Axes, sizes, loading/empty, formatting, legend:** as in the input table.
- **Alternative table:** each type toggles to its table and back. Line shows exact values (`1234`, not `1.2K`) with `Category` plus series columns; scatter shows `Series`/`X`/`Y`, bubble adds `R`; donut shows `Label`/`Value`.
- **Interactions:** hover shows one shared tooltip (`role="tooltip"`) that retargets between marks and disappears when the pointer leaves; focus shows the same tooltip; Tab enters at the roving tab stop and leaves to the Table button; arrow keys, Home, and End move the roving tab stop and DOM focus.

Omitted on purpose (unsupported or not a Chart feature): zoom/pan, donut center text or sum, configurable inner radius, log or clamped value axes, custom empty or loading content. None is invented on the page.

## Source discrepancies and known gaps

The ten discrepancies recorded when this page was written were closed by Plan 24 (2026-10-05):

1. **Axis titles** are drawn from `axes.xTitle` and `axes.yTitle`; see "Axis titles" on the page.
2. **Scatter tooltip point** carries data units in `KuiChartPoint.x` and `y` and passes `r`; the default text is `{series}: ({x}, {y})`.
3. **Arrow keys** move DOM focus; the former `test.fixme` is a passing test.
4. **Event replay:** e2e still waits for hydration before keyboard steps; the replay log was not re-investigated.
5. **SSR ids** come from an application-scoped sequence, so server and client ids are equal; `chart-contract.spec.ts` compares them.
6. **Built-in English strings** are `chart` messages with Playground catalogue entries.
7. **Bar loading skeleton** shrinks with its container; the page no longer gives it a full-width row, and an e2e test checks there is no overflow.
8. **Axis padding and density** follow measured text widths and the measured container width; the page shows dense, narrow and titled charts.
9. **Stale JSDoc** was corrected (eight series tokens, full default tooltip text).
10. **Loading designs** still have no approved source (docs/design-provenance.md); marker shapes and hatch patterns are recorded there as engineering decisions awaiting designer confirmation.

New groups: "Dense data, narrow containers, titles and patterns" (dense line, axis titles, narrow line and bar, patterns on bar, area and donut) and "Stress test" (button-activated 500, 2000 and 5000 points; measured numbers in docs/chart.md).

## E2E scope

`e2e/chart-playground.visual.spec.ts` uses `getByRole` for groups, buttons, tables, status, columns, and tooltips; charts and marks are located by their ARIA roles and attribute values because Playwright does not model `graphics-document` or `graphics-symbol`. It covers server HTML and hydration without console errors, the minimal example, every input above, legend, table, tooltip, and roving-tab-stop keyboard behavior, EN/RU with a runtime switch (Russian text is read from `ru.json`, never hardcoded), page-level overflow at 768px and 320px, and named screenshots:

- Desktop: `chart-minimal`, `chart-minimal-light`, `chart-minimal-focus-visible`, `chart-line-area`, `chart-bars`, `chart-bars-stacked-hidden`, `chart-scatter-bubble`, `chart-donut`, `chart-axes`, `chart-sizes`, `chart-states`, `chart-formatting`, `chart-legend`, `chart-legend-custom-hidden`, `chart-tables`.
- Tablet 768px and mobile 320px: `chart-minimal`, `chart-line-three`, `chart-donut` (three slices), `chart-scatter-loading`, `chart-line-empty`.

The viewport is 2400px tall so every named group sits inside the shell's scrolling workspace when captured. The shared route spec (`component-pages.spec.ts`) includes `/components/chart` in its SSR, hydration, selected-navigation, and 320/768/1440 overflow checks.
