## States, semantics, and edge behavior

- The selector only decorates native `button` and `a` hosts. The page uses both, supplies an accessible label on each icon-only control, and keeps action/navigation semantics native. The docs require accessible labels and recommend buttons for actions and anchors for navigation.
- The stylesheet defines hover, active, focus-visible, focus-without-visible, disabled, loading, and reduced-motion behavior. Hover and active styling varies by shape; sizes map to square control dimensions (xs 28px, sm 32px, md base 40px, lg 44px). The page captures actual pointer hover and active states on the default ghost button, and checks `:focus-visible` after keyboard Tab navigation.
- Under `prefers-reduced-motion: reduce`, transitions are disabled and the active transform is removed. The Playwright spec emulates no-preference and reduced motion, verifies the active scale under the former, then verifies `transition-property: none` and `transform: none` under the latter.
- Loading adds a centered status spinner and preserves the footprint while hiding the underlying icon visually. `projects/ui/src/lib/components/icon-button/kui-icon-button.directive.ts:130` hard-codes the status accessible label as `Loading`; this is an inherited library localization limitation, and this page does not claim that label changes with the playground locale. The page test locates it by role/name in English.
- The enabled navigation example is a native anchor with `href="/components/icon-button#icon-button-states"`. The states group owns that id, and the Playwright flow checks that activation retains the component route, updates the URL hash, and reaches the named target.
- The default screenshot waits for the browser-created, registered SVG before capture. This matters because the directive skips DOM mutation during SSR and creates the named icon in a browser effect; the icon resolver itself is asynchronous. The E2E setup intercepts jsDelivr Lucide requests and returns fixed, page-local SVG fixtures so screenshots do not depend on network availability or upstream icon changes. The library resolver endpoint is covered separately by its unit spec.

The [Playground example-card component](../../../components/playground-example-card/playground-example-card.html) wraps examples in a KUI Card with a heading. Single-control visual snapshots target named native button/link controls; the focus screenshot captures the full states group so the visible focus ring remains inside the crop. The four matrix screenshots intentionally target their wide, labeled 20-control grids. The responsive E2E captures the extra-small matrix at 320px and 768px, checks workspace scrolling and page overflow at both widths, and checks the named shape groups occupy two columns at 768px. Both responsive captures were generated and visually inspected after the fresh SSR build.

## Deliberate omissions and docs notes

- Hover, active, disabled, loading, focus, and reduced-motion behavior are demonstrated or asserted on representative controls, not crossed through all 80 matrix cells. The default ghost/no-appearance control is used for hover, active, and reduced-motion checks; static primary/solid and primary/outline examples cover disabled and loading. The matrices provide the complete appearance/shape/size axis coverage.
- The page does not demonstrate a persistent pressed/selected/toggle state: the directive exposes no `pressed`, `selected`, or `aria-pressed` input/state. `:active` is transient CSS behavior only.
- The page does not separately enumerate an empty `icon` input state or dynamically update/clear a name; these transitions are covered by the directive spec. It also does not exercise a named icon failure/network-error state; the default resolver may return `undefined` for an unknown/unavailable name.
- The Playground config has no scoped button defaults or root size default, so the no-input example shows the directive fallbacks (`ghost`, null appearance, `md`). Scoped and root size precedence is covered by library tests rather than a provider-configured page variant.
- The visual spec checks a 320px viewport, asserts the document does not overflow horizontally, confirms the shell workspace owns vertical scrolling, and captures the extra-small matrix in its one-column mobile layout. At 768px it asserts the page does not overflow, verifies the named shape groups use two columns, and captures the extra-small matrix. Both responsive captures were generated and visually inspected after the fresh SSR build.
- Documentation lists all six inputs and the scoped/root defaults, but it does not explicitly state `appearance` resolves to `null` or that boolean `disabled`/`loading` default to `false`. Its size input text names root fallback, while source option typing establishes that scoped button size takes precedence over root size. This inventory follows source behavior for those details.
