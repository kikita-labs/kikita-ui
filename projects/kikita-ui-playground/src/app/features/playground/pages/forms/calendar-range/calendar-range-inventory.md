# Calendar Range Page Inventory

Source audit of `kui-calendar-range` and the page that exercises it. Contract sources: `docs/calendar-range.md`, `projects/ui/src/lib/components/calendar-range/kui-calendar-range.component.ts` (inline template, inputs, models), its unit spec, `projects/ui/src/lib/components/calendar/kui-calendar.types.ts` and `kui-calendar-date.util.ts`, `projects/ui/src/lib/utils/kui-calendar-navigation.util.ts`, `projects/ui/src/lib/i18n/kui-calendar-locale-text.util.ts`, `projects/ui/src/lib/components/calendar/kui-calendar.css`, and the Calendar page inventory. Behavior below was verified in the browser through the page's E2E spec and throwaway probes.

## Discrepancies and library findings (recorded, not fixed)

- **Arrow keys do not move DOM focus** (`test.fixme` reproduces it). `onGridKeyDown` queries the tab stop in `queueMicrotask` before the re-render, so focus stays on the previous cell and lags one keypress; `kui-calendar` uses `afterNextRender`. The page tests assert the roving tab stop and re-focus it between keys.
- **No tab stop after leaving today's month** (`test.fixme`). `focusedDate` starts at today and there is no `ngOnInit` re-anchor like `kui-calendar`'s; after Next month no cell has `tabindex="0"`.
- **Announcements**: docs say month and year changes use the live region; only picking a month from the month grid writes to it (verified `June 2026`); the Next/Previous buttons, keyboard month changes and year picks announce nothing (`test.fixme`).
- **Decade label mismatch**: the year view header reads `2021–2032` while the grid shows `2020`–`2031` (first and last muted). Inherited from Calendar.
- **`sm` keeps its border**: docs say `sm` drops border and padding; CSS keeps the border and only `sm` + `flat` removes padding.
- **Hover preview**: mouse only (keyboard movement never previews), it persists after the pointer leaves the grid until a click, and hovering a disabled date previews through it and marks it as the preview end.
- **`aria-selected` on the hovered day**: while a range is open the hovered day receives `aria-selected="true"` as the preview end; docs describe it only for committed endpoints.
- **Stale classes across SSR locale mismatch**: `KUI_LOCALE` defaults to `navigator.language`, so the server renders in the Node locale. When it differs from the browser locale, the hydrated grid keeps server-applied classes on shifted cells (selected and range classes visibly landed on the neighbouring day in an initial run). The page therefore sets `locale="en-US"` on every English example. Root Calendar baselines may be affected in environments where the server locale differs.
- **Markup** (fixed in Plan 10.3): the day grid is a complete ARIA grid (`grid > row > gridcell > button`) and `aria-selected` sits on the gridcell; axe reports no violation on this route (matching `/components/calendar`). Library-owned strings (grid label "Calendar", Previous/Next labels, "Today") are English in Russian.
- Docs and unit tests agree with the implementation otherwise; the unit spec covers grid size, `aria-current`, range building, normalization, hover preview, `minDate`, `data-kui-size`, keyboard Enter, footer toggle and Russian month names.

## Omitted combinations

- `[kuiCalendarHeader]`/`[kuiCalendarFooter]` projection, root-provider size defaults and other locales: reasons above.
- `showWeekend=false` is shown only with the date limits; the visual difference is identical elsewhere.
- Every supported input value appears at least once; combinations beyond those shown are visually equivalent.
