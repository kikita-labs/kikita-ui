## Source discrepancies and limits

- `docs/color-input.md` says once that hex enables a browser-native color picker, but the directive source only creates the Kikita picker dialog and never creates or calls `<input type="color">`. This page follows implementation and unit tests; the documentation sentence is a source/docs mismatch and is not reproduced as behavior.
- The visible Invalid catalogue row uses a valid color and explicit `invalid`; parser invalidity is covered as a separate interaction. The page does not claim malformed input is a field-level translated error message; the parser only sets `aria-invalid` and the invalid wrapper state.
- The generated chevron name/tooltip, hue name, 2D slider name, L/C/H captions, hex editor name, Copy text, and preset accessible names are hard-coded in English. Only examples that bind `swatchLabel` follow runtime locale; the minimal example intentionally keeps the input default `Open color picker`. No page API can translate the library-owned strings.
- Touch-target measurements from the shipped CSS/theme are below the repository's 44×44px touch target guidance (`.agents/accessibility.md`): swatches are 16px (`xs`), 20px (default), or 24px (`lg`); the field chevron is 24×24px; preset swatches are 24×24px; and the `xs` Copy button uses the 28px control-height token. Input heights resolve to 28/32/40/44px for `xs`/`sm`/`md`/`lg`. The page records these inherited library dimensions without changing component visuals or claiming the small generated actions meet the touch target rule.
- The custom popover is viewport-width constrained by the shipped style; the page captures its normal desktop interaction, while 320px tests assess catalogue layout and document overflow. Extreme zoom, forced colors, OS picker behavior, assistive-technology review, and other browsers are not claimed by these tests.
