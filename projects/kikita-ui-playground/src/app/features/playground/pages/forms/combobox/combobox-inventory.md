# Combobox Page Inventory

This inventory is a retrospective source audit of the Combobox page. It was cross-checked against `docs/combobox.md`, `projects/ui/src/lib/components/combobox/index.ts`, the directive, highlight pipe and mode type, the Combobox/Field option tokens and providers, `projects/ui/src/lib/components/combobox/kui-combobox.directive.spec.ts`, the Dropdown/Field/Option composition, and `projects/ui/src/styles/combobox.css` plus the inherited Field styles.

`docs/design-provenance.md` has no Combobox-specific approved visual record, and `docs/combobox.md` documents the API and behavior rather than approval evidence. This page-only correction changes option values to match their current translated labels and adds interaction assertions; it does not add or restyle a visual state.

## Public contract mapping

| `value` model             | `T \| string \| null`, default `null`; generates `valueChange`. In filter/async modes, editing query clears selected value; selecting a `kuiOption` stores its value and writes `kuiLabelFn(value)` or `String(value)` to the native input. Free mode stores typed text as value. | Filtering binds object value two-way and selects Daniel; async binds an object; free mode binds string. Primitive option values in the default, free, and field-state examples now use the current translated visible label, so selection keeps the input label aligned in EN/RU. E2E asserts the selected value in both interaction paths. |

| `kuiLabelFn`              | `((item: T) => string) \| undefined`; default fallback is `String(value)`.                                                                                                                                                                                                        | Object examples bind `personLabel` to show a person's name instead of `[object Object]`; free text and string examples do not need it.                                                                                                                                                                                                      |
| `placeholder`             | `string`, default `''`.                                                                                                                                                                                                                                                           | Each page field uses a concise translated placeholder; the Russian E2E verifies the live translated placeholder. | `mode`                    | `KuiComboboxMode`, default `'filter'`; documented values are `'filter'`, `'free'`, and `'async'`.                                                                                                                                                                                 | Default/filter example, free-input example, and consumer-filtered async example. `async` means filtering remains the consumer's responsibility; its page fixture uses deterministic local signals/data and does not simulate a network request.                                                                                             |
| `clearable`               | Optional boolean; effective order is local input > `KUI_COMBOBOX_OPTIONS` > `KUI_FIELD_OPTIONS` > `true`.                                                                                                                                                                         | Inherited/default clearable input and a local `[clearable]="false"` override are shown. E2E clears the selected value, checks focus restoration and `data-has-clear`, then verifies the hidden action on the override. Provider-level alternatives are omitted because the page does not own app configuration.                             |
| `loading`                 | Boolean input, default `false`; shows a loading suffix; projected row content remains consumer-owned.                                                                                                                                                                             | Loading suffix and projected loading row are shown in the affordances group and asserted after opening the field. Loading with an existing value/query is omitted; the suffix renders the loader in place of the clear action, and no distinct approved visual combination is recorded.                                                     |

`value` and `query` are Angular `model()` inputs, so `valueChange` and `queryChange` are generated outputs. The page binds both models in the filtering example; selection updates `value`, and native edits update `query`. `search` and `touch` are explicit outputs. The page's async scenario binds `query` and `search` to consumer-controlled results but does not emulate asynchronous transport.

The public `KuiComboboxHighlightPipe` accepts `(label: string, query: string | null | undefined)` and returns readonly `{ text, match }` segments typed as `KuiComboboxHighlightSegment`; it trims the query and matches case-insensitively. The filtering example renders these matches. `kuiProvideComboboxOptions` accepts `KuiComboboxOptions` (the `KuiFieldControlOptions` alias with `readonly clearable?: boolean`) and feeds the documented precedence chain. Provider setup is omitted because it belongs to app configuration; the focused component test covers provider resolution.

## Source-backed behavior and inherited limitations

- Public exports and API declarations: `projects/ui/src/lib/components/combobox/index.ts` and `kui-combobox.directive.ts`. Mode type and provider fallback are sourced from the adjacent mode/token implementation; docs spell out provider priority.
- The control remains a native `<input>` and uses `role="combobox"`, `aria-haspopup="listbox"`, dynamic `aria-expanded`/`aria-controls`, `aria-autocomplete`, and Field-provided ID/description/error semantics. Options are provided by the sibling `kui-dropdown`/`kuiOption` composition.
- Suffix action accessible names `Clear`, `Open options`, and `Close options` are hardcoded English in `kui-combobox-input-suffix.component.ts`. Russian page labels/placeholders update, but those inherited primitive controls do not; the locale E2E does not claim otherwise.
- The page's disabled/no-match/loading content rows use ordinary `<div>` elements rather than live status roles. This page-level composition limitation is documented rather than hidden by the inventory.
- FormValueControl inputs `errors`/`touched` and output `touch`, an explicit ID override, provider configuration, and real remote transport are omitted for the concrete reasons in the API mapping above. Signal Forms `[formField]` wiring is not a page scenario; the page uses `[(value)]` and tests direct invalid state plus native Field error association. Selection context methods are exercised through the composed option interaction instead of direct calls.
- Relevant styling comes from `projects/ui/src/styles/combobox.css` and Field/Input styles. Page SCSS uses KUI spacing tokens and responsive layout only; it does not restyle the Combobox primitive.
