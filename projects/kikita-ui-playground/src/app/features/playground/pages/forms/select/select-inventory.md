Primitive selected values are displayed with `String(value)` unless `kuiLabelFn` is supplied. ## Touch-target source measurements

- Select inherits native input height from `kui-field`: the shipped size tokens are `xs` 28px,
  `sm` 32px, `md` 40px, and `lg` 44px. This route has no root size default, so its default controls
  resolve to `md` at 40px; only the shown `lg` size reaches the Playground's 44px target height.
- The generated Select clear and chevron buttons use a 20×20px hit box. Selected-value chips use
  the shipped `sm` chip height of 22px, and their remove buttons are 12×12px. These measurements
  are below the Playground's 44×44px touch guidance for `xs`/`sm`/`md` inputs, suffix actions, and
  chip removal. They are inherited library dimensions; this page records the limit and preserves
  shipped visuals without claiming touch-target compliance.

## Source and documentation discrepancies

- `docs/select.md` omits the public `id` input and describes `errors` as `ValidationError[]`; source accepts `readonly WithOptionalFieldTree<ValidationError>[]`.
- An explicit `id` inside a `kui-field` with its own `label` overrides the Select input's generated field ID, but the field label still targets `controlId`. That breaks the native label association. The default keeps the generated ID; the explicit-ID example uses a separate native label and omits the field's `label` input so both cases remain accessible.
- Field control IDs are generated by an application-scoped service rather than module state, so separate SSR requests do not carry a counter into hydration. The shared SSR test now makes two prior Select requests, compares the default Field label and Select ID in the raw server response, then verifies hydration preserves that ID and label association. This regression is added but remains unverified until the parent runs the shared SSR/browser gate.
- The keyboard table does not make clear that opening does not also select: Select opens and focuses an enabled option, then a second Enter/Space selects it.
- Signal Forms binds its raw `invalid` state to the directive's `invalid` input, which `effectiveInvalid()` ORs with the field's touched-gated invalid state. The field error message remains hidden until touch, but `aria-invalid` may be present before touch. This is library interop behavior; the page asserts the user-visible error only after the real close/touch transition.
- The generated clear and open/close suffix button labels are hard-coded in English (`Clear`, `Open options`, `Close options`), as are default chip-removal labels. The Russian E2E verifies translated page-owned names, status and text-mode values, object/team/role option labels, provider-default values, and custom-removal labels; it does not claim that library-generated action labels are localized.
- In multiple readonly mode, the default chip-removal affordance remains enabled-looking, but its handler ignores removal because the Select is readonly. A custom `kuiSelectValue` template likewise owns its remove button's disabled presentation while the callback is a no-op. The page avoids this misleading combination and shows readonly as a single-value control with the library's actual disabled clear button.
- The custom `kuiSelectValue` remove button is supplied by consumer template markup; the library does not disable that button when readonly. Its callback becomes a no-op. This page uses the public removal callback only in the enabled custom-template example.
- The `maxVisibleChips` suffix clamps negative values to zero visible chips; its numeric transform accepts positive `Infinity`, which `slice(0, Infinity)` uses to show every selected item. Zero, negative, and infinite caps are omitted because the default three-chip and local two-chip examples already show normal overflow behavior without advertising atypical configurations.
- No Select-specific approved design record appears in `docs/design-provenance.md`. Examples preserve the shipped Select/input, Field, chip, dropdown, and listbox visuals; page SCSS only arranges layout with Kikita spacing tokens.
- `KuiSelect` does not add `aria-multiselectable` to the listbox. The page does not claim that attribute exists.
- The directive compares object and multiple values by identity; it has no `compareWith` input. Fixtures retain stable object references.
- No loading, typeahead, filtering, empty-result, or async state exists in the public Select contract; those states are omitted.
- Provider-only `clearable` and `maxVisibleChips` overrides are shown in a page-private component provider scope so they do not alter the other catalogue examples; the normal three-chip fallback and local two-chip override remain visible separately.
- `placeholder` defaults to `''`, but the minimal single-select example uses a concise prompt alongside its visible Field label and hint; a separate empty-placeholder panel would not show a meaningful state. Multiple examples with selected values also omit placeholder text.
- When `multipleDisplay="text"` omits `multipleTextFn`, source joins labels with comma-space. That fallback is not a separate example because the page demonstrates both default chip mode and the optional custom text formatter.
- Select exposes no density input. Although the token docs describe root and local `data-kui-density` scopes, the browser measured `padding-inline-start: 16px` on the default Select with no attribute and with root-level `data-kui-density="compact"`; the nested compact scope also measured 16px. The page omits compact/comfortable visuals rather than overriding the shared tokens locally.
- Axe 4.12 reports one `region` violation on the app-wide `.cdk-overlay-container` while the Select listbox is open because the CDK portal is outside the page landmark. The closed-state scan excludes only that empty mount point when it exists; the open-state scan retains the violation and asserts its exact target. Select's combobox/listbox relationships, option states, and keyboard behavior remain covered separately. Before scanning, the E2E check waits for the shell-injected `#playground-theme` and verifies that dark selected text/background tokens resolve to palette tones 4/11; selected options stay included in axe coverage.
