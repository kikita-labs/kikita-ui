# Date Picker Page Inventory

This page presents the public `input[kuiDatePicker]` API with the documented `kui-field`,
`kui-dropdown`, and sibling `kui-calendar` pairing. Demonstration field values are fixed to May
2026; parser edge cases use fixed years 0000 and 0001. The minimal Default leaves `viewDate`
unbound so it follows the public current-month default. Visual E2E examples install a May 14, 2026
browser clock; the JavaScript-disabled SSR check verifies the empty named field and closed panel,
not a current-month value.

This is a **retrospective contract audit completed before handoff**. The page implementation began
before this audit, so this inventory does not claim that the full contract was audited before the
first implementation. The current source types are `value: Date | null`, `viewDate: Date`,
optional `minDate` and `maxDate` of type `Date`, boolean `disabled`, `readonly`, `invalid`, and
`touched`, `errors: readonly WithOptionalFieldTree<ValidationError>[]`, `touch: Output<void>`,
optional string `id`, string `placeholder`, and optional boolean `clearable`. Angular `model()`
also generates `valueChange: Output<Date | null>` and `viewDateChange: Output<Date>`.

Malformed nonempty text sets invalid while preserving the previous parsed model value. A
parseable date outside `minDate` or `maxDate` updates `value` and `viewDate`, remains invalid,
and is disabled in the linked Calendar. Parsing trims surrounding whitespace before validating
the exact date-token format; a successful parse is formatted back into the input. Four-digit
years from `0000` through `9999` are preserved, and the year is rendered with four digits.
Typing an empty string does not itself clear a previously parsed model; the explicit clear action
sets `value` to `null` and restores focus to the input.

The Date Picker docs name the Signal Forms `invalid`, `errors`, `touched`, and `touch` members but
do not list their individual types/defaults or state that `touch` emits after an opened dropdown
closes; this inventory records that source contract and maps the touch flow to the Signal Forms
browser scenario.
The page uses Field to associate its generated native label and its optional hint/error ids, Dropdown
to position and dismiss the calendar panel, and an internal Date Picker affix component for the
calendar, clear, and toggle controls. The internal affix component currently uses Field's deprecated
`kuiFieldAffixIcon` and `kuiFieldAction` compatibility directives; they remain supported and are not
part of the Date Picker page API. These composition dependencies are not additional Date Picker
inputs. The dropdown source names `listbox`/`grid` panels but deliberately skips automatic name
binding for `dialog`; the Date Picker panel therefore remains unnamed. The Date Picker and Dropdown
accessibility docs do not specify a name for this `panelRole="dialog"` composition, so this is also
a docs/source coverage gap. Calendar's grid name (`Calendar`) and the internal affix labels
(`Clear`, `Open calendar`, `Close calendar`) are hard-coded in library source and remain English
when the page language is Russian. No page-level API can correct those inherited name/localization
gaps; they are unresolved library issues and are not claimed as covered.

The audit was completed after initial page implementation, not before it. A page-owned SSR test
checks JavaScript-disabled server-rendered markup followed by a hydrated keyboard interaction; its
server-side assertions cover the named empty field and closed panel, and its hydrated interaction
opens the Calendar under the fixed May 2026 browser clock. Earlier browser/build results predate the
minimal-default and assertion changes in this revision. The visual spec's coverage is intentionally
described by viewport above, not as a full desktop/tablet/mobile matrix for every state; only the
open Default panel capture is expected to change because its displayed month moved from June to May.

## Verification notes

- 2026-09-28: the Russian labels check failed 1/5 in isolated repeats and once in the full
  serial playground gate. Running the unchanged spec with `--repeat-each=20 --workers=1`
  reproduced it 2/20, both at the final weekday poll. The traces show the observed cause: the
  English panel was closed with Escape and the Russian ArrowDown followed about 135ms later.
  `KuiDropdownComponent.close()` only starts the 120ms `kui-dropdown-out` animation and keeps
  `isOpen()` true until `animationend`, so `KuiDatePickerDirective` treated the ArrowDown as
  "focus the grid" instead of "open". The closing panel already rendered the Russian month, so the
  month check passed, then the overlay detached and the weekday row was never found. The spec now
  waits for the English dialog to be hidden and `aria-expanded="false"` after Escape, and for
  `aria-expanded="true"` plus a visible dialog after the Russian ArrowDown. With the fix the
  check passed 20/20 in serial repeats and the whole Date Picker spec passed 14/14 with no capture
  changes. That first fix also added scope-reload hardening in `beforeEach`, a wait for the client
  re-fetch of `/i18n/date-picker/en.json`; that race was never observed in the failing traces.
  The re-fetch itself was then removed at the source in `91ec517` (the shared loader now uses a
  relative URL on both platforms, so hydration reuses the server-loaded catalogues and boot makes
  no `/i18n/` requests). The hardening wait could no longer resolve and was removed;
  `beforeEach` now opens the route and waits for the translated heading, and the closing-animation
  waits stay. Re-verified against a build of `91ec517`: the check passed 20/20 in serial repeats
  and the whole Date Picker spec passed 14/14 with no capture changes. The library behavior (ArrowDown ignored as an open
  request while the panel is closing) is reported to the library owners rather than changed here.
