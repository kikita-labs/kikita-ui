## Public contract map

`KuiSwitch` is exported from the package root. Its selector is `input[type=checkbox][kuiSwitch]`; the native checkbox remains the value and interaction control. It adds the `kui-switch` class and `role="switch"`.

A field's own effective size is `kui-field[size]` → `defaults.field.size` → root default → `md`. The current Playground root provider sets only `scrollbars`, so an unconfigured switch resolves to `md`. | Default example omits `size` and asserts `data-kui-size="md"`. ## Discrepancies and verification gaps

- The public docs omit the `invalid` default and the `defaults.field.size` step in the field-size fallback chain. They also omit the Switch CSS variables and do not have stable accessibility, keyboard, or CSS-hook sections. The source and [default guidance](../../../../../../../../../docs/di-defaults.md) are more complete than the current Switch page docs.
- Explicit `id` inside `kui-field` can break the shorthand label association: `KuiField` points its label at `controlId`, while `KuiSwitch.hostId` lets the explicit input ID replace that target. The current Switch unit spec only covers the generated-ID path. Keep the explicit ID example standalone until the contract or implementation is corrected and covered.
- CSS styles `[readonly]` as disabled, but native checkbox semantics do not prevent activation for a readonly attribute. This appearance is not a supported readonly state.
- Checked-thumb movement uses physical `translateX(...)` while its starting inset is logical `inset-inline-start`; there is no Switch-specific RTL override. This suggests checked-thumb direction may be wrong in RTL. RTL behavior is not documented or covered by the current English/Russian Playground locales. The current page remains LTR and makes no RTL claim; the library direction behavior still needs a separate decision and verification.
- Switch CSS has transitions but no Switch-specific `prefers-reduced-motion` or `forced-colors` rule. The approved visual record should specify these treatments before they are claimed as reviewed.
- The Switch directive itself reads no browser globals and is structurally SSR-safe. Field IDs are generated from a module-level counter in `KuiField`; the Switch unit tests are client-side only. The page-owned E2E passes no-JavaScript server markup, generated field label/description references, and a clean hydration reload on the integrated route.
- The Switch unit spec checks standalone class/role/size/invalid and field-generated ID/hint/error wiring. It does not exercise native toggling, disabled behavior, keyboard input, explicit IDs, root defaults, Signal Forms, SSR, or the CSS state matrix. The legacy page shows basic states, but fakes hover/focus with page CSS; its state coverage is not interaction evidence.
- The 1.6.1 changelog records a fix for Signal Forms overwriting the control's `invalid` input before the field's touched gate. Preserve that behavior in the live form scenario.

No separate screen-reader/assistive-technology review is recorded. The SSR build, E2E results, and screenshot review described in Status are the current browser/SSR evidence; they do not constitute an assistive-technology review or an approved Switch-specific visual record. Do not describe assistive-technology review as complete based only on DOM and keyboard assertions.

## Proposed page and browser evidence

The implementation uses the agreed compact component-page anatomy: one `Switch` heading and five visible `PlaygroundExampleCard` sections for default, sizes, invalid/disabled states, real interactions, and field/form behavior. Page styles arrange examples only; shipped `kuiSwitch` styling owns the control visuals.

1. **Default and sizes:** a minimally configured, explicitly labelled standalone switch omits `size` and resolves to `md`; the size matrix shows `xs`, `sm`, `md`, and `lg` both off and on.
2. **States and interaction targets:** invalid off/on and disabled off/on. Separate `md` pointer and keyboard targets produce actual `:hover`, `:focus-visible`, and `:active` states in the browser.
3. **Field and form:** inherited field size, a local Switch-size override, generated ID and hint references, plus a live Signal Forms switch that starts untouched, becomes invalid on blur, and clears after native activation. The explicit input ID stays standalone with a native `<label for="switch-default">` because `kui-field` shorthand labels retain the ID mismatch.

The page-owned `switch-playground.visual.spec.ts` targets `/components/switch` and uses named roles for interaction and assertions. It verifies native click and Space toggling, disabled non-activation, checked state, invalid/description references, explicit standalone ID labeling, field-size inheritance and local override, and Signal Forms error appearance/clearance. It also checks server-rendered semantics with JavaScript disabled and runtime errors after a hydrated reload. All 7 Switch tests pass.

The spec captures deterministic named-section screenshots at desktop and at 320px for all five catalogue sections, including the interactions card. It also captures representative light- and dark-shell evidence and real hover, focus-visible, and pointer-down states; checks page-level overflow at 320px, 768px, and desktop widths; and switches `en` to `ru` before checking localized validation copy. The baselines were generated and visually reviewed.

The parent used the serial verification slot for the fresh SSR build and browser run; results are recorded above.
