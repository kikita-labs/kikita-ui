## Semantics, state, and behavior

The documentation recommends native `article`, `section`, `aside`, `button`, and `a` hosts according to content and behavior. The semantic-host example includes all five: a named article, a named section (region), a named aside (complementary), an anchor to the default example, and a button. Headings name the article, section, and aside; native link and button roles remain available to assistive technology. The E2E test reaches the anchor by keyboard, activates it with Enter, and asserts its real `#card-default-target` destination. Its route segments come from `PlaygroundRoute`. It reaches the button by keyboard and verifies that Enter and Space run the page-owned demo action, which updates a polite live output. The Card directive itself declares no event, output, activation, role, tabindex, or keyboard behavior; native hosts provide semantics and activation.

The [Card stylesheet](../../../../../../../../ui/src/styles/card.css) defines these supported visual states and edge behavior:

- `surface` is the base background, border, and shadow treatment. `elevated` and `sunken` select their corresponding theme surface, border, and shadow tokens.
- `xs` and `sm` reduce padding, `md` uses the base padding, and `lg` increases padding. The stylesheet has explicit overrides for `xs`, `sm`, and `lg`; `md` is the unmodified base.
- `interactive` adds a pointer cursor, hover border/shadow, and `:focus-visible` outline. The hover is intentionally subtle in the dark baseline: the base and hover borders resolve to low-chroma neutral theme colors, and the hover shadow is a low-opacity black shadow. The Playwright check reads the surface card's computed base border color, resolves the documented `--kui-card-border-hover` token, then verifies hover changes the actual computed border color to that token. The page captures this actual pointer state and reaches focus by keyboard Tab navigation on a native button.
- `prefers-reduced-motion: reduce` disables the Card transition. The focused Playwright spec deterministically emulates both `no-preference` and `reduce` and checks the interactive card's computed `transition-property` changes from the declared transitions to `none`; the preference remains stylesheet behavior, not a configurable Card input or a separate appearance variant.
- The directive styles its host but does not add `role`, `tabindex`, keyboard handlers, or native activation. Therefore the interactive examples use focusable native `button` and `a` elements; no generic `div` is presented as an interactive Card.

The 320px viewport captures each matrix as three named appearance groups (`surface`, `elevated`, and `sunken`), with all four sizes shown for every appearance. The four-card static groups fit in one capture apiece. Interactive groups are taller than the shell workspace, so each is captured as two adjacent native button pairs (`xs`/`sm`, then `md`/`lg`); the page clip is bounded to the visible pair inside the workspace scrollport. The five semantic hosts, focus, hover, and activation output are also captured as individual targets so screenshots stay within the workspace. Before capture, the test collapses the `Actions` and `Surfaces` accordions through the named `Component navigation` landmark, scrolls each target into the shell workspace, and asserts no document-level horizontal overflow. The test uses the accessible navigation and accordion names rather than shell CSS classes. The shell has no mobile navigation hide control, so its existing accordion controls are the accessible way to reduce navigation content. At 768px, the static and interactive matrices have named card-position assertions for their two-column layout and capture separate tablet screenshots after checking document overflow. Server-rendered markup and hydration are checked by the focused Playwright spec. Its baseline captures explicitly start in the shell's dark theme; a browser scenario compares all three Card appearance backgrounds after switching to light, then verifies that switching back restores their dark values. English and Russian resources use matching keys in `public/i18n/card/en.json` and `ru.json`; the spec switches to Russian and checks the document language plus translated heading, example group, and default article name.

## CSS theming contract

The docs list the Card-specific custom properties below. They remain the library's public theming hooks; the page uses the active theme and does not inject custom values or recreate Card styling. The [theme generator](../../../../../../../../ui/src/lib/theme/create-kui-theme.ts) supplies component variables, and its [tests](../../../../../../../../ui/src/lib/theme/create-kui-theme.spec.ts) explicitly check the elevated and sunken shadow variables.

- Backgrounds: `--kui-card-bg`, `--kui-card-bg-elevated`, `--kui-card-bg-sunken`.
- Borders: `--kui-card-border`, `--kui-card-border-elevated`, `--kui-card-border-sunken`, `--kui-card-border-hover`.
- Shape and spacing: `--kui-card-radius`, `--kui-card-padding`.
- Shadows: `--kui-card-shadow`, `--kui-card-shadow-elevated`, `--kui-card-shadow-sunken`, `--kui-card-shadow-hover`.

## Unsupported states and justified omissions

- Card exposes no `active`, `pressed`, `selected`, or Card-owned `disabled` input/state, and its stylesheet defines no corresponding selector. The page does not imply those states. Native `button` disabled behavior is not demonstrated because disabled is outside this directive's API.
- There is no `sizeChange` / `appearanceChange` output, click output, or built-in navigation. Button activation count and anchor navigation are consumer composition examples, not Card API behavior.
- Transient hover and keyboard focus-visible are demonstrated on representative interactive buttons rather than repeated for all 12 interactive combinations; the two matrices establish the full appearance/size coverage while the interaction screenshots establish the shared state styles.
- Root-size inheritance is not configured in the page because the Playground's [application config](../../../../../app.config.ts) sets styled scrollbars only. Inherited-size resolution is nevertheless covered by the library integration test linked above; the page's unconfigured fallback is visible and asserted as `md`.
- The page does not enumerate the 13 CSS variables as editable variants or override them, because they are styling hooks rather than Card inputs and the task is to demonstrate the existing KUI visuals without inventing a theme treatment.

## Source audit notes

The previous source documentation omitted `size`; [`docs/card.md`](../../../../../../../../../docs/card.md)
now lists all three inputs, their defaults, native semantics, consumer-owned keyboard activation,
and the public style entrypoint. The directive test verifies the elevated and interactive host
attributes, while the root-default integration test verifies inherited `sm`; the page E2E maps the
full appearance/size matrix and style states to accessible examples. The Playground app config does
not set a root size default, so the page's omitted-size instance demonstrates the `md` fallback.
