# Tooltip page contract inventory

This source-backed inventory reflects the implemented page and its authored browser evidence. It is based on [`docs/tooltip.md`](../../../../../../../../../docs/tooltip.md), [`KuiTooltipDirective`](../../../../../../../../ui/src/lib/components/tooltip/kui-tooltip.directive.ts), its [placement and trigger types](../../../../../../../../ui/src/lib/components/tooltip/kui-tooltip-placement.type.ts), [trigger enum](../../../../../../../../ui/src/lib/components/tooltip/kui-tooltip-trigger.type.ts), [scoped defaults](../../../../../../../../ui/src/lib/tokens/kui-tooltip-options.token.ts), [overlay utility](../../../../../../../../ui/src/lib/utils/kui-tooltip-overlay.util.ts), [surface](../../../../../../../../ui/src/lib/components/tooltip/kui-tooltip-surface.component.ts), [unit tests](../../../../../../../../ui/src/lib/components/tooltip/kui-tooltip.directive.spec.ts), [runtime CSS](../../../../../../../../ui/src/styles/tooltip.css), and [theme token generation](../../../../../../../../ui/src/lib/theme/create-kui-theme.ts). `kuiTooltip` is exported by the component barrel and root public API, and `tooltip.css` is included by `kikita-ui.css`.

The tooltip has no page-specific approved visual design record in `docs/design-provenance.md`. This page changes no Tooltip visuals; it uses the agreed fixed catalogue surface and the shipped `kuiTooltip`, button, icon-button, card, and typography visuals. The parent integrated its route fragment, `provideTranslocoScope('tooltip')`, and shared SSR/adaptive route registration. The parent-owned `component-pages.spec.ts` already includes `/components/tooltip` in direct-route SSR/hydration, selected-navigation, and responsive checks; this page-owned spec adds Tooltip-specific SSR and interaction assertions.

The icon-only trigger uses a fixed, trusted inline SVG through `kui-icon`'s `source` input instead of starting the default Lucide CDN resolver. This keeps the Tooltip SSR and screenshot examples independent of Icon network resolution; the dedicated Icon page owns resolver evidence.

## Public contract audit

| Public API                                  | Type and default/resolution                                                            | Observed behavior and evidence                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kuiTooltip` input                          | `string`, defaults to `''`.                                                            | `show()` trims it and ignores empty/whitespace-only values. No overlay or `aria-describedby` is created for either.                                                                                                                                                                                                                                                                                                         |
| `placement` input                           | `KuiTooltipPlacement` = `'top' \| 'bottom' \| 'left' \| 'right'`, defaults to `'top'`. | Selects one CDK connected position with a 6px gap. The strategy uses `withPush(false)` and supplies no fallback positions. Surface exposes the requested side in `data-kui-placement`.                                                                                                                                                                                                                                      |
| `triggerType` input                         | `KuiTooltipTrigger \| undefined`, defaults to `undefined`.                             | Local value wins over the resolved `KUI_TOOLTIP_OPTIONS.triggerType`. Supported values are `auto`, `hover`, `click`, and `none`.                                                                                                                                                                                                                                                                                            |
| `KUI_TOOLTIP_OPTIONS` / `KuiTooltipOptions` | Options object with optional `triggerType`; root factory defaults to `auto`.           | The minimally configured examples resolve the root `auto` default. A scoped `kuiProvideTooltipOptions({ triggerType: 'hover' })` example and local `triggerType="click"` override demonstrate nearest-provider and local precedence. Separate `provideKikitaUi()` and raw-token provider examples are omitted because they configure the same modes at a different injector scope and add no distinct Tooltip visual state. |
| Outputs and models                          | None.                                                                                  | The directive exposes no outputs or model inputs.                                                                                                                                                                                                                                                                                                                                                                           |
| `showWithText(text)` method                 | Public method on the exported directive, returns `void`.                               | In a browser, creates a tooltip at the host or updates the existing tooltip. Its JSDoc says Slider uses it, but Slider instead manages its own internal `KuiTooltipOverlayHandle`.                                                                                                         |

Slider, Color Input, and Chart call the similarly named `updateText()` on the internal `KuiTooltipOverlayHandle`, not this public directive method.                                                                                                                                                      |
| `KuiTooltipTriggerType`                     | Public enum for `Auto`, `Hover`, `Click`, `None`; values are lowercase strings.        | Enum and `KuiTooltipTrigger` string-union type are exported from the public barrel.                                                                                                                                                                                                                                                                                                                                         |

## Test and source findings

The library unit suite currently covers the described-by lifecycle, CDK overlay role/class/placement, empty and whitespace text, repeated pointer-enter idempotence, adaptive touch opening and outside-click dismissal, scoped-provider defaults, and local input precedence over a scoped provider. It does not directly cover keyboard activation/focus-visible, `click` toggling, `none`, Escape/focus-out tap dismissal, reduced motion, the mobile visibility rule, edge positioning, the public directive methods, or SSR. Slider, Color Input, and Chart do use `updateText()` on the separate internal `KuiTooltipOverlayHandle`; do not mistake those calls for coverage or use of the public directive method. The authored page E2E covers real hover/focus, all trigger modes, supported placements, blank text, wrapping, provider precedence, touch opening and dismissal, reduced motion, mobile visibility, Russian scope loading, and the four catalogue groups at desktop and 320px. The shared spec separately checks direct-route SSR/hydration, selected navigation, and responsive viewport fit. On 2026-09-27 the page-owned Angular SSR build passed, the focused Tooltip Playwright suite passed 10/10 on a clean run after snapshot regeneration, and all 23 resulting PNGs were visually inspected. The integrated shared route/responsive suite remains parent-owned.

The source roadmap records a known WCAG 1.4.13 gap: Escape does not dismiss hover/focus-open tooltips, and the surface is not hoverable, so moving the pointer from the trigger onto the tooltip dismisses it. Only tap-open mode installs Escape dismissal. The page must not imply those hover-mode behaviors are supported or fully compliant.

## Discrepancies and deliberate omissions

- `docs/tooltip.md` says the directive appends a fixed `<div>` to `body`, but the implementation and changelog say it renders `kui-tooltip-surface` through Angular CDK Overlay. The Tooltip page will assert the accessible surface contract and not depend on the outdated DOM construction description.
- The adaptive trigger implementation treats both `touch` and `pen` pointer types as tap-capable, while the public docs describe touch input. The page demonstrates touch behavior; pen-specific testing is omitted because it follows the same adaptive path and does not create a distinct visual state.
- The exported directive declares `showWithText()` and `updateText()` as public methods, but neither method appears in the Tooltip API docs, has direct unit coverage, nor has an external consumer call. `showWithText()`'s JSDoc claims Slider uses it, but that appears stale: Slider, Color Input, and Chart call the internal overlay handle's `updateText()` instead. The directive method also bypasses normal trigger/blank-text checks and does not install tap dismissal. The page will omit these undocumented imperative methods and preserve the discrepancy for library-owner follow-up.
- The overlay requests only one position and disables push/fallback. The page will demonstrate the four documented sides with centered triggers; viewport-edge fallback/push behavior is not claimed or simulated.
- Tooltip API has no size, appearance, shape, density, disabled-state, validation, loading, selected, or form inputs. No such catalogue combinations will be added. Trigger host appearance examples belong to Button/Icon Button and will be kept to the minimum needed for accessible Tooltip triggers.
- Tooltip CSS custom properties theme the shared surface through the app's existing theme controls. No per-page style overrides are shown because they would restyle the library primitive instead of demonstrating a supported Tooltip variant.
- `provideKikitaUi({ tooltip: ... })` and a direct `KUI_TOOLTIP_OPTIONS` value can change the same effective trigger default, but their application/injector registration has no distinct rendered state beyond the existing default and scoped-provider examples; separate wiring demonstrations are omitted.
- Formal assistive-technology review is not established by the source inspection, unit suite, or planned Playwright checks; it remains a separate review level.
