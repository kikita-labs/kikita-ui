# Alert Contract Inventory

This inventory maps the complete local public Alert contract to the Playground examples. `kui-alert` is an inline, controlled notification: it never removes itself, has no timer, no overlay, and no Escape handling. The consumer owns removal, focus management, and any translated copy.

**Audit timing:** source-backed audit completed before any page file was written. The audit was accepted by the parent before implementation; this file was then updated to the implemented page. The mapping below reflects what shipped.

## States and semantics

- Live region: `danger` is announced assertively, all others politely. A region inserted by `@if` after user action is the realistic use; the page has one such scenario that inserts a status alert and an alert alert. Actual screen-reader announcement is not verifiable in Playwright; the test asserts the role/`aria-live`/`aria-atomic` attributes only, and the report records that no assistive-technology pass was run.
- The host is not focusable. Only the action and close buttons are tab stops; tab order is action then close. Keyboard test covers Tab, Enter, and Space on both.
- Escape does nothing: the live regions and dismissal scenario presses Escape with focus inside an alert and asserts the alert stays.
- Focus, hover, and pressed states are produced with real input on the close button and action button (real `hover()` and keyboard focus) before capture; no page CSS fakes a pseudo-state.
- Single-line centering: title-only or message-only alerts without an action get `data-kui-single-line`; the matrix and size example cover the centered and top-aligned layouts.
- Narrow widths: 320px captures show wrapped titles and messages; a browser test asserts no document overflow at 320px, 768px, and desktop.
- No disabled, readonly, invalid, loading, or selected state exists in the contract.
- Theme: dark is the shell default; one light-theme capture of the matrix is taken by switching the real shell theme button.

### Discrepancies and library observations

1. The docs "Import" block lists `KuiAlertActions`, `KuiAlertIcon`, `KuiAlertMessage` but omits `KuiAlertTitle`, although `[kuiAlertTitle]` is documented and exported from `index.ts`. Fixed in `docs/alert.md` in the page commit (docs gap, no behavior impact).
2. The docs API table states `size` defaults to `'md'`; the implementation resolves local input, then the root `defaults.size` (only `sm`/`md`), then `md`. `docs/alert.md` now states the resolution order (fixed in the page commit).
3. The class JSDoc and docs use `<kui-icon kuiAlertIcon name="cloud-off">` as the projected icon example. `kui-icon` resolves names asynchronously (CDN fetch), which conflicts with deterministic screenshots and the component's own "no async chrome" note. The page uses an inline `<svg>` instead; this is a page choice, not a defect.
4. `docs/state-coverage.md` row 95 and the note at line 130 describe the legacy `/alert` page ("dismissed state tracked by the demo", "committed baselines not run"). The parent must replace that with the new `/components/alert` evidence after integration.
5. The unit spec does not assert `(closed)`/`(action)` outputs for projected actions, Escape inertness, banner geometry, root size default, or `closeLabel` override. The page browser tests cover these behaviors; no defect is implied.
6. `docs/alert.md` records the 28px close hit target below the 44px platform guidance as a known kit limitation (inherited from Toast). Not a page defect; recorded for the report.

No reproducible library defect was found. Observations, not defects: (a) removing the alert that holds the focused close button drops focus, which is expected for a controlled component; the page returns focus to the trigger; (b) in the light theme the neutral `solid` shape shows white text on a light taupe fill (`alert-appearance-shape-light`); contrast was not measured because the axe sweep excludes `color-contrast`, so this is a visual note for the color plan only; (c) the neutral `soft` shape is barely distinguishable from the card surface in the dark theme.

## Planned page (mapping)

All examples use fixed English/Russian copy from the `alert` Transloco scope; names below are the group labels used by tests (`role="group"`).

1. **Default**: `<kui-alert message="...">`, everything else default (`neutral`, `soft`, `md`, closable, no icon).
2. **Appearance and shape**: three groups (Soft, Outline, Solid), each with the five appearances (title + message + close). 15 alerts. Screenshot per group at desktop and 320px.
3. **Size and content**: `sm` and `md` groups, each with title-only, title + message, message + action (one appearance, `success`), showing centered versus top-aligned bodies.
4. **Banner**: stacked banners for all five appearances and one title + message banner.
5. **Options**: `showIcon` false, `closable` false, neutral with `showIcon` true, custom translated `closeLabel`.
6. **Custom content**: projected icon (inline svg), the same icon on a neutral alert with `showIcon` false, projected title with a badge (the `title` input is also supplied and shown to be ignored), and projected message with an anchor.
7. **Actions**: one alert with `actionLabel` and a visible click counter (pointer, Enter, Space); one alert with projected Retry and Discard buttons, whose own handlers run while the `(action)` output stays silent.
8. **Live regions and dismissal**: buttons insert a polite status alert (success) and an assertive alert (danger); closing by pointer or keyboard removes the alert and returns focus to its trigger; Escape leaves an open alert in place.

Browser evidence: real hover, keyboard focus on the action and close buttons, Tab order (action then close), EN/RU switch (including the translated `closeLabel`), a light-theme matrix capture, held-script SSR hydration, and no document overflow at 320px, 768px, and desktop.

## Omitted combinations

- Root `defaults.size` provider: the Playground sets no `defaults`; adding a provider only for this page would change page scope. The fallback and local override (`sm`, `md`) are shown; precedence is owned by the shared defaults contract (as Badge records).
- Full cross product (5 appearances x 3 shapes x 2 sizes x content variants): omitted beyond the 15-cell appearance/shape matrix and the size/content matrix, because size and content variants do not alter appearance tokens; this is stated here rather than shown as 90 near-duplicate alerts.
- `showIcon` x every appearance: `neutral` and one non-neutral appearance cover both branches of the contract.
- Auto-dismiss, timers, overlay, Escape close: not part of the contract (the page asserts Escape is inert).
- Disabled, readonly, invalid, loading, selected: not in the contract.
