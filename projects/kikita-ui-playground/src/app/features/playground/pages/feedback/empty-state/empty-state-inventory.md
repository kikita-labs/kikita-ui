# Empty State Contract Inventory

This inventory maps the complete local public contract to the Playground examples. The component owns layout, text presentation, and context/size attributes; consumers provide optional content, accessibility semantics, and actions.

**Audit timing:** this is a retrospective contract audit completed during self-review before handoff. Before the first page file, I read the public component docs/source, design provenance and authoring rules, and consulted the component/API/example MCP surfaces. The full signatures/defaults/types/CSS/unit-test cross-check and example-to-contract map were completed after the initial implementation; they were not a pre-code gate.

The component template projects `[kuiEmptyStateIcon]` before its text body and `[kuiEmptyStateActions]` after it. Both are optional content selectors, not value inputs, and neither slot has a default element. The body conditionally renders a `div.kui-empty__title` for truthy `heading` and a `div.kui-empty__description` for truthy `description`. Consequently omitted/`undefined` heading and omitted/`null` description are the defaults; empty strings suppress their respective nodes. `context` defaults to `no-data`. `size` resolves as local `size ?? provideKikitaUi({ defaults: { size } }) ?? 'md'`, where the injected root size is used only if it belongs to `sm | md | lg`. The checked-out Playground config has no root size setting, so the default example resolves to `md`. There are no outputs or component-owned control states.

All four public inputs are signal inputs; a parent can update text and `data-kui-*` attributes reactively. The catalogue binds the complete finite context/size domains from page data, while the live-filter example demonstrates the intentional user-driven state transition. A property-selector control is omitted because it would turn this usage catalogue into an API editor. Checked Angular templates reject unsupported context/size values; if untyped JavaScript bypasses the context union, the value is reflected in `data-kui-context` without receiving a context-specific icon accent.

The following meaningful combinations and state changes are covered: text with neither slot (default), heading-only, description-only, all contexts with decorative icon, all sizes with icon plus native link, action-only with three links, and filtered results → dynamic no-results host → cleared/restored results with a native button. An icon-only composition is deliberately omitted: the public icon directive sets `aria-hidden="true"`, so a decorative icon alone has no accessible explanation; the page never presents it as meaningful state content. Icon-plus-action without text is omitted for the same reason. The fully empty host omission is described below. There is no built-in loading/error-alert/validation/focus/disabled state: `context` only sets a data attribute and (for three values) an icon accent, while focus and activation belong to the projected native controls.

There are no component outputs, models, or built-in loading, validation, selection, disabled, focus, hover, or pressed states. Those states are inapplicable to this presentational primitive. Native interactive state belongs to projected controls. The page provides real keyboard use for the projected link and button; it does not fake control pseudo-states with page CSS.

The completely empty host (no heading, description, icon, or actions) is intentionally omitted. Although the API permits it, it has no visible or accessible content and communicates no state; the default example supplies a description, and the heading-only, description-only, and action-only examples cover the meaningful content compositions.

The page and component use declarative templates/signals without browser globals or lifecycle-dependent DOM work, so their implementation is SSR-safe. Browser-only viewport and URL checks live in the Playwright spec.

## Visual and responsive coverage

- The page shows the minimal default; heading-only, description-only, and action-only compositions; all five contexts; all three sizes; no-icon/no-action and icon/action projections; and a real dynamic no-results interaction.
- The size catalogue uses concise copy in both locale catalogues so the shipped horizontal `sm` arrangement stays legible at narrow widths. No `kui-empty` styles are overridden.
- The action-only composition uses three native links to existing page examples. Their total width exercises the component's documented `flex-wrap` action layout; it adds no made-up Empty State behavior.
- At widths below `64rem`, the page switches its three-column size catalogue to one column so the horizontal `sm` example has the full available workspace width. At `768px`, the visual spec captures the small-size example and checks that the size examples stack without document overflow.
- The full context-by-size cross product is omitted because all context values have the same documented layout at a given size and all size values have the same context-specific icon accent behavior. Each complete domain is shown independently, including the `md` default.
- Actions are omitted from the context catalogue because action-slot examples appear at every size, in the action-only composition, and in the live-filter scenario. Context rows do not need repeated actions to expose a context-specific behavior.
- Page wrapper styles control only layout and use `--kui-space-*` tokens. The 320px visual spec captures individual labelled context/size/action-only examples and the live status region to avoid clipping in the Playground's short nested scroll viewport; it asserts no document-level horizontal overflow before and after filtering.
- The Empty State SVG is copied from the local component usage example. The page does not add or restyle Empty State chrome. `design-provenance.md` has no Empty State-specific row in its preserved-decisions table; existing appearance is therefore taken from the tracked component docs and shipped CSS, while the Playground contributes only tokenized layout.

## Discrepancies and limits

- Workspace docs and component source agree that `heading` is optional; the cached MCP API copy says required. The checked-out source is the implementation authority used here.
- Source unit tests cover fewer behaviors than the public docs. This page adds concrete examples for heading-only, description-only, and action-only content, multi-action wrapping, projected link/button behavior, dynamic `role="status"`, and status removal after clearing; there is no unsupported Empty State state to add.
- The list-result state uses Angular's `@for (...) { ... } @empty { ... }` branch, rather than a separate length check. The empty branch stays a valid `ul` child (`li[role="presentation"]`) and contains the live `kui-empty-state[role="status"]`; restoring results removes that status node.
- The provenance matrix does not contain an Empty State-specific approved visual record. No component visual was created or changed; the page uses the documented SVG and the existing public component/CSS output.
