# i18n

Present only because this project opted into i18n. Delete this file (and its `AGENTS.md`
link) if that questionnaire answer was "no".

Approach: Transloco with HTTP-loaded JSON catalogues in `public/i18n/` and runtime language switching.

- Locale catalogues contain the language that users read. English-only repository rules do not
  apply to values in `public/i18n/*.json`; source code, tests, and documentation remain English.
- Read [i18n-json-architecture.md](./i18n-json-architecture.md) before adding a key, language,
  scope, loader, or validation rule.

- No hardcoded user-facing strings in templates or components. Every string a user sees
  goes through the chosen i18n mechanism.
- Keys/messages are named by feature and purpose (`user.card.title`), not by their English
  text.
- Date, number, and currency formatting always goes through Angular's locale-aware pipes
  (`DatePipe`, `DecimalPipe`, `CurrencyPipe`) or the runtime library's equivalent — never
  hand-rolled formatting.
- New locales get added to the build config and to this file's approach note, not silently.
