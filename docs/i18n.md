# Internationalization

Kikita UI separates two things an application can change:

| What         | Controls                                                                                     | Configured with |
| ------------ | -------------------------------------------------------------------------------------------- | --------------- |
| **Locale**   | Month and weekday names, week start and weekend, date and time layout, numbers, plural rules | `locale`        |
| **Messages** | The library's own text: accessible names, visible words, placeholders, hints, announcements  | `messages`      |

They are independent on purpose. Set a locale to format dates in German while the labels stay English, or supply French messages while dates keep the locale of the request.

The library ships **English only**. A translation is a typed object that your application owns (or a community package provides); `KuiMessages` is the contract for it.

## Quick start

```ts
// app.config.ts
import { provideKikitaUi, type KuiMessagesLayer } from '@kikita-labs/ui';

const german: KuiMessagesLayer = {
  pagination: { next: 'Weiter', previous: 'Zurück' },
  calendar: { today: 'Heute' },
};

provideKikitaUi({ locale: 'de-DE', messages: german });
```

A message is a string, or a function with one named parameter object for text that depends on values:

```ts
const german: KuiMessagesLayer = {
  pagination: {
    summary: ({ start, end, total }) => `${start}–${end} von ${total}`,
  },
};
```

Only the keys you write change. Every other key keeps its English default, and a group you leave out stays English.

### Follow the application's language at runtime

Pass a `Signal`. The library re-renders its labels when the signal changes; nothing is recreated.

```ts
provideKikitaUi({
  locale: () => inject(LanguageService).locale, // Signal<string>
  messages: () => inject(LanguageService).messages, // Signal<KuiMessagesLayer>
});
```

`locale` and `messages` also accept a plain function; it runs in an injection context, so it can `inject()` services. You can also change them later with `KuiI18n`:

```ts
inject(KuiI18n).setLocale('fr-FR');
inject(KuiI18n).setMessages(frenchMessages);
```

### Override a subtree

`provideKuiI18n`, `provideKuiLocale` and `provideKuiMessages` add a level to a component, a route or an environment injector. A level inherits the locale and the messages of its parent and changes only what it names. Two subtrees never affect each other.

```ts
@Component({
  providers: [
    provideKuiI18n({ locale: 'fr-FR', messages: { calendar: { today: "Aujourd'hui" } } }),
  ],
})
```

### Override one instance

| Mechanism            | Where                                                                                                                                                                                   |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Explicit label input | `ariaLabel`, `closeLabel`, `label`, `swatchLabel`, `errorLabel`, `placeholder`, `emptyText`, `removeLabel` and the other single-purpose label inputs keep working and win over messages |
| `messages` input     | Components that own four or more messages: Calendar, Calendar Range, Carousel, the charts, Color Input, Command Palette, Date Picker, File Upload, Pagination, Time Picker              |
| Per-call data        | `kuiMediaViewer({ messages })`, `kuiConfirm({ confirmLabel, cancelLabel })`                                                                                                             |
| `locale` input       | Calendar and Calendar Range                                                                                                                                                             |

For every other component, use a subtree level.

### Precedence

```text
explicit label input > messages input > nearest level > outer levels > provideKikitaUi > English
```

Merging is per group and per key. `undefined` inherits; an empty string is a real value and an empty accessible name is the application's choice.

## Writing a translation

`KUI_ENGLISH_MESSAGES` is the complete English pack and the best starting point: copy it, translate the values, and the compiler checks every key. `KuiMessages` documents each key with its English default.

Function messages receive a second argument with locale helpers:

| Helper                        | Use                                                                               |
| ----------------------------- | --------------------------------------------------------------------------------- |
| `ctx.locale`                  | The resolved locale tag                                                           |
| `ctx.formatNumber(n)`         | A number with the locale's grouping and decimal separators, Latin digits          |
| `ctx.plural(n, { one, ... })` | The form `Intl.PluralRules` selects: `zero`, `one`, `two`, `few`, `many`, `other` |

```ts
fileUpload: {
  tooMany: ({ max }, { formatNumber, plural }) =>
    `Maksymalnie ${formatNumber(max)} ${plural(max, { one: 'plik', few: 'pliki', many: 'plików', other: 'pliku' })}`,
},
```

Messages are text only. Do not put HTML in them. Text that you pass to a component (titles, option and tab labels, error text, tooltip content, `acceptLabel`) is yours and is never translated by the library.

### Use a translation library

Messages are plain functions, so any translator fits without a library dependency. Wrap the translator in a function and keep it reactive:

```ts
provideKikitaUi({
  messages: () => {
    const transloco = inject(TranslocoService);
    const catalogue = toSignal(transloco.selectTranslateObject('kui'));
    return computed(() => toKuiMessages(catalogue()));
  },
});
```

The [Playground](../projects/kikita-ui-playground/src/app/shared/utilities/kui-messages/create-kui-messages-layer.ts) keeps the Kikita UI messages in its Transloco catalogues (`public/i18n/en.json` and `ru.json`, key `kui`) and converts them with a 70 line adapter: templates with `{name}` placeholders and plural or boolean variants chosen by one parameter. It is a reference implementation, not a library API.

## Locale

### Where it comes from

```text
Calendar locale input > nearest level > provideKikitaUi({ locale }) > KUI_LOCALE
```

`KUI_LOCALE` resolves to the first usable `Accept-Language` language of the request on the server, hands it to the browser through `TransferState` so the first client render matches the server HTML, and falls back to `navigator.language` and then `en-US`. The host's own locale is never read on the server. Responses vary by `Accept-Language`; a cache in front of the server must send `Vary: Accept-Language`, or pin a locale with `provideKuiLocale`.

Angular's `LOCALE_ID` is not read implicitly, because it cannot tell "unset" from `en-US`. To follow it:

```ts
provideKikitaUi({ locale: () => inject(LOCALE_ID) });
```

### Unsupported or malformed locales

A requested tag is canonicalized and checked against the runtime's `Intl`. The fallback chain is the full tag, then `language-script`, then `language`, then `en-US`. Development builds warn once when the locale falls back. The server needs full ICU data (the default in Node 13 and later); otherwise a locale such as `ru-RU` can fall back on the server and render differently from the browser.

### What the locale controls

| Area                                    | Behavior                                                                                                                                                                                                                            |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Calendar                                | Month and weekday names; heading `month year` in the locale's order; first day and **weekend** of the week from `Intl.Locale#getWeekInfo()`, with a static fallback for older engines; every day button is named with its full date |
| Date Picker                             | Field order and separator of the numeric date (`10/03/2026`, `03.10.2026`, `2026/10/03`). Parsing reads digit groups, so `3.1.2026` is accepted; the year needs four digits. `format` pins a layout                                 |
| Time Picker                             | 12 or 24 hour default from the locale's hour cycle, the separator (`:` or `.`), the day period text and its position. Typing accepts the locale's `AM`/`PM` text and ASCII `am`/`pm`                                                |
| Pagination, Carousel, Media Viewer, OTP | Counts and positions are formatted with the locale                                                                                                                                                                                  |
| Charts                                  | The default value format is the locale's compact notation (`1.2K` in English, `1,5 Mio.` in German)                                                                                                                                 |
| File Upload                             | Sizes use `Intl` units (`2.5 MB`, `340 kB`) and progress uses a percent format                                                                                                                                                      |

Dates are formatted in the Gregorian calendar with Latin digits whatever the locale's default is, and calendar names are taken from UTC midnight, so the time zone never moves a day.

### Limits in v2

Right-to-left layouts, native (non-Latin) numerals and non-Gregorian calendars are not supported. Text remains translatable in those languages; layout and digits follow the LTR Latin rules.

## Accessibility

- Accessible names come from the same messages as visible text, so a translation changes them together. Every name is non-empty by default.
- The library does not set `lang` or `dir`. When the language of the messages differs from the page language, mark the document or the subtree that carries the scope with `lang` (WCAG 2.2 SC 3.1.2 Language of Parts).
- Calendar day buttons are named with the full localized date (`Saturday, October 3, 2026`) and the grid, month and year controls with messages, so a screen reader gets the context a bare day number lacks.

## Server rendering

Locale and messages are plain data held per injector; the library keeps no module-level locale state and its formatter caches live in the `KuiI18n` instance, so one request never sees another's. Identical sources on the server and the client give identical HTML. A `Signal` source that loads asynchronously (a translator fetching a catalogue) should resolve before the first render or be provided with the transfer cache, as the Playground does.

## Testing a translation

Wrap every message of the English pack in a marker and render your screens: any accessible name without the marker is text that bypasses the message map. The library's own `kui-messages.integration.spec.ts` does this, and `pnpm audit:static` fails on literal English in component templates, documents every key and checks the Playground catalogues.

## Migrating from v1

| v1                                                                         | v2                                                                                                           |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Built-in English text could be changed per instance only                   | `messages` for the app or a subtree, plus the `messages` input on larger components                          |
| `provideKuiLocale(locale)` returned one `Provider`                         | Returns `Provider[]` and sets the locale of a `KuiI18n` level; it accepts a `Signal` and works for a subtree |
| `KUI_LOCALE` was the only locale source                                    | Still the root source; read the effective locale with `KuiI18n.locale`                                       |
| Date Picker always used `dd.MM.yyyy`                                       | Follows the locale; set `format="dd.MM.yyyy"` (or `defaults.datePicker.format`) to keep the old layout       |
| Time Picker defaulted to `24h`                                             | Follows the locale; set `format="24h"` (or `defaults.timePicker.format`) to keep it                          |
| `placeholder` of Date Picker defaulted to `dd.mm.yyyy`                     | Built from the `datePicker` placeholder messages in the order of the locale                                  |
| `ariaLabel`, `label`, `closeLabel` and similar inputs had English defaults | The inputs are `undefined` when omitted and resolve through messages; passing a value behaves as before      |
| Calendar weekends were always Saturday and Sunday                          | They follow the locale (Friday and Saturday in `he-IL`, Friday in `fa-IR`)                                   |
| Chart values used a fixed `K`/`M`/`B` format                               | Locale compact notation; pass `valueFormat` to keep a fixed format                                           |
| File sizes read `KB`/`MB`                                                  | `Intl` units: `kB`, `MB`                                                                                     |
| `Maximum 1 files`                                                          | `Maximum 1 file`                                                                                             |
| Day buttons were named with the day number                                 | Named with the full date                                                                                     |

## CSS variables

Not applicable: messages and locale are runtime configuration and have no CSS hooks.

## Reference

| API                                     | Purpose                                                                      |
| --------------------------------------- | ---------------------------------------------------------------------------- |
| `provideKikitaUi({ locale, messages })` | Root locale and messages                                                     |
| `provideKuiI18n({ locale, messages })`  | Level for a subtree                                                          |
| `provideKuiLocale(locale)`              | Locale only                                                                  |
| `provideKuiMessages(messages)`          | Messages only                                                                |
| `KuiI18n`                               | `locale`, `messages`, `context`, `get(group)`, `setLocale`, `setMessages`    |
| `KuiMessages`, `KuiMessagesLayer`       | The full message map and its partial override                                |
| `KuiMessageContext`, `KuiPluralForms`   | Helpers passed to function messages                                          |
| `KUI_ENGLISH_MESSAGES`                  | The English pack                                                             |
| `KUI_LOCALE`                            | Root locale source (request, transfer state, navigator)                      |
| `getKuiCalendarLocaleText(locale)`      | Month and weekday names, first day and weekend for a locale (pure, no cache) |
